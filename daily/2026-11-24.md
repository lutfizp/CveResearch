# Daily Log — 2026-11-24

- CVE: CVE-2026-11265 (Chromium issue 500262869; CWE-940)
- Platform: Windows
- Category: info_leak
- Trigger: browser_application
- Trigger detail: Chrome for Testing **148.0.7778.96** (win64, pre-fix) opens the
  lab victim page `victim.test:8821` with an embedded cross-site iframe
  `attacker.test:8822`; the user Autofills the e-mail field inside the attacker
  iframe (real Autofill popup + `kFill`), and the browser delivers an EVP
  SD-JWT+KB assertion. Fixed control: Chrome for Testing **149.0.7827.53**.
  Flags: `--enable-features=EmailVerificationProtocol`,
  `--ignore-certificate-errors`, `--host-resolver-rules` mapping the four lab
  host names to 127.0.0.1, `--no-proxy-server`, `--no-sandbox`.
- Outcome: pre-fix, the attacker iframe receives an assertion whose EVT `email`
  is `avery.synthetic@corp.cve11265.test` and whose KB-JWT `aud` is
  `http://victim.test:8821` (the victim/parent origin), even though the token is
  delivered to the attacker field frame. Replaying the stolen assertion to the
  synthetic victim backend returns the account PII: name
  `Avery Synthetic Marlowe`, phone `+1 415 555 0142`, address
  `742 Evergreen Terrace, Springfield, CA 90210`, account marker
  `CVE_MARKER_11265_ACCOUNT`. On 149.0.7827.53 the assertion is
  `aud=http://attacker.test:8822` and the victim backend returns HTTP 403
  `audience_mismatch`.

- Blockers: none for the lab reproduction. Limitations documented in the
  README: the attacker iframe is autofilled, so the e-mail string is also
  visible in the fixed build; the security boundary is the victim-scoped KB-JWT
  `aud` (and the victim account data it unlocks). The lab victim backend
  validates audience + e-mail, not a server-side nonce; the nonce in the stolen
  assertion is attacker-chosen (`CVE11265_ATTACKER_NONCE`). A strict
  nonce-binding backend would reject the replay.
